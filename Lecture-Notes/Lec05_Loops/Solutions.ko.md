## 연습 문제 1: 거북이의 무작위 이동

**문제:** 거북이가 무작위 길이만큼 이동하고 무작위 각도만큼 회전하는 동작을 30번 반복하게 하라. 문제 전문과 실행 예시는 [연습 문제 1](Exercises.ko.md#연습-문제-1-거북이의-무작위-이동)에 있다.

### 풀이

**접근 방법:** 같은 동작을 정해진 횟수인 30번 반복하므로 `for`문과 `range(30)`을 쓴다([5강 3.1절](Concepts_Lecture.ko.md#31-range종료값)). 반복할 때마다 수행할 알고리즘은 다음과 같다.

- [1, 100] 사이의 난수를 발생하여 변수 `length`에 저장한다.
- 거북이를 `length`만큼 움직인다.
- [-180, 180] 사이의 난수를 발생하여 변수 `angle`에 저장한다.
- 거북이를 `angle`만큼 회전시킨다.

난수는 `random` 모듈(4강)의 `random.randint(a, b)`로 만든다. 이 함수는 `a` 이상 `b` 이하의 정수 하나를 같은 확률로 돌려주며, 양 끝값 `a`와 `b`도 나올 수 있다. `t.right(angle)`에 음수 각도를 주면 거북이는 그 절댓값만큼 왼쪽으로 회전하므로, [-180, 180] 사이의 각도는 왼쪽과 오른쪽의 모든 방향 전환을 포함한다.

**코드:**

```python
import turtle
import random
t = turtle.Turtle()
t.shape("turtle")

for i in range(30):
    length = random.randint(1, 100)   # random length in [1, 100]
    t.forward(length)
    angle = random.randint(-180, 180) # random angle in [-180, 180]
    t.right(angle)
```

**실행 결과:** 프로그램은 텍스트를 출력하지 않고 터틀 그래픽 창에 경로를 그린다. 거북이는 모두 30번 앞으로 이동하고 30번 회전하며, 난수 때문에 실행할 때마다 다른 경로가 그려진다. 한 실행의 예는 연습 문제 1의 그림 1과 같다.

- **`import random`:** 난수를 만드는 표준 모듈을 불러온다.
- **`t.shape("turtle")`:** 화살표 모양의 기본 커서를 거북이 모양으로 바꾼다.
- **반복 본체:** 네 문장이 알고리즘의 네 단계에 그대로 대응한다. 루프 변수 `i`는 본체에서 쓰지 않으며 반복 횟수를 세는 역할만 한다.

> **참고:** 실행할 때마다 같은 경로를 얻고 싶으면 반복문 앞에서 `random.seed(1)`처럼 난수 생성기의 시작값을 고정한다. 같은 시드를 주면 같은 순서의 난수가 만들어지므로, 무작위성이 있는 프로그램을 시험하거나 결과를 다시 만들 때 유용하다.

## 연습 문제 2: 팩토리얼 계산

**문제:** 정수 $n$을 입력받아 $n! = 1 \times 2 \times \cdots \times n$을 `for`문으로 계산하여 출력하라. 문제 전문과 실행 예시는 [연습 문제 2](Exercises.ko.md#연습-문제-2-팩토리얼-계산)에 있다.

### 풀이

**접근 방법:** 곱을 누적하는 문제이다([5강 5.2절](Concepts_Lecture.ko.md#52-곱의-누적과-팩토리얼)). 누적 변수 `fact`를 곱셈의 항등원인 1로 초기화하고, `range(1, n+1)`로 1부터 $n$까지 반복하며 `fact`에 차례로 곱한다.

- **입력:** `input()`이 돌려주는 문자열을 `int()`로 정수로 바꾼다(2강).
- **반복:** 종료값은 범위에 포함되지 않으므로 $n$까지 곱하려면 종료값을 `n+1`로 준다.
- **출력:** `print()`에 결과를 넘긴다.

**코드:**

```python
n = int(input("정수를 입력하시오: "))

fact = 1
for i in range(1, n+1):
    fact = fact * i
print(n, "!은", fact, "이다.")
```

**실행 결과:**

```text
정수를 입력하시오: 10
10 !은 3628800 이다.
```

입력이 5일 때 `fact`의 변화는 다음과 같다.

| `i` | 1 | 2 | 3 | 4 | 5 |
|:-----|:---:|:---:|:---:|:---:|:---:|
| 본체 실행 후 `fact` | 1 | 2 | 6 | 24 | 120 |

*표 1. 5!을 계산할 때 누적 변수 fact의 변화*

출력에서 `10`과 `!은` 사이, `3628800`과 `이다.` 사이에 공백이 생긴 것은 `print()`가 쉼표로 구분한 값 사이에 공백 한 칸을 넣기 때문이다([5강 2.2절](Concepts_Lecture.ko.md#22-루프-변수의-활용)). 실행 예시처럼 공백 없이 출력하려면 % 서식(3강)으로 문자열 하나를 만들어 출력한다. 다음 코드는 음수가 입력되는 경우도 함께 처리한다.

```python
n = int(input("정수를 입력하시오: "))

if n < 0:
    print("음수의 팩토리얼은 정의되지 않는다.")
else:
    fact = 1
    for i in range(1, n+1):
        fact = fact * i
    print("%d!은 %d이다." % (n, fact))
```

```text
정수를 입력하시오: 10
10!은 3628800이다.
```

```text
정수를 입력하시오: 0
0!은 1이다.
```

```text
정수를 입력하시오: 30
30!은 265252859812191058636308480000000이다.
```

```text
정수를 입력하시오: -3
음수의 팩토리얼은 정의되지 않는다.
```

- **0을 입력한 경우:** `range(1, 1)`은 빈 범위이므로 본체가 한 번도 실행되지 않고, `fact`는 초깃값 1을 유지한다. 이 값은 정의 $0! = 1$과 일치한다.
- **음수를 입력한 경우:** 처음 프로그램에서는 `range(1, n+1)`이 빈 범위가 되어 `-3 !은 1 이다.`라는 잘못된 결과를 출력한다. 팩토리얼은 음이 아닌 정수에만 정의되므로, 고친 프로그램은 `if` 문(4강)으로 음수를 먼저 걸러 내고 `음수의 팩토리얼은 정의되지 않는다.`를 출력한다.

> **참고:** 파이썬의 정수는 크기 제한이 없어서 30!처럼 큰 값도 정확히 계산한다. 반면 C 언어의 64비트 정수형이 표현할 수 있는 최댓값은 $2^{63} - 1 = 9223372036854775807$이므로, $20! = 2432902008176640000$까지는 저장할 수 있지만 $21! = 51090942171709440000$부터는 넘친다.

## 연습 문제 3: 구구단 한 단 출력

**문제:** 원하는 단을 입력받아 그 단의 `단*1`부터 `단*9`까지를 출력하라. 문제 전문과 실행 예시는 [연습 문제 3](Exercises.ko.md#연습-문제-3-구구단-한-단-출력)에 있다.

### 풀이

**접근 방법:** 곱하는 수 `i`를 1부터 9까지 바꾸며 9번 반복한다. 여기서는 카운터로 제어하는 `while`문을 사용한다([5강 6.3절](Concepts_Lecture.ko.md#63-카운터로-제어하는-반복)).

- **초기화:** 곱하는 수 `i`를 1로 둔다.
- **조건:** `i <= 9`인 동안 반복한다.
- **갱신:** 본체의 끝에서 `i = i + 1`로 1을 더한다.
- **출력:** `"%s*%s=%s" % (dan, i, dan*i)`는 `%` 연산자를 이용한 문자열 형식화(3강)로 세 값을 문자열 안의 `%s` 자리에 차례로 넣는다. `%s`는 값을 문자열로 바꾸어 넣으므로 정수에도 쓸 수 있으며, 값 사이에 공백이 생기지 않는다.

**코드:**

```python
dan = int(input("원하는 단은: "))
i = 1

while i <= 9:
    print("%s*%s=%s" % (dan, i, dan*i))
    i = i + 1
```

**실행 결과:**

```text
원하는 단은: 9
9*1=9
9*2=18
9*3=27
9*4=36
9*5=45
9*6=54
9*7=63
9*8=72
9*9=81
```

9번째 반복에서 `i`가 10이 되면 조건 `i <= 9`가 거짓이 되어 반복이 끝난다. 반복 횟수가 9로 정해져 있으므로 `while`문 대신 `for i in range(1, 10):`을 쓰면 초기화와 갱신 문장 없이 같은 결과를 얻는다([5강 7.1절](Concepts_Lecture.ko.md#71-변환-방법)).

## 연습 문제 4: 구구단 전체 출력

**문제:** 연습 문제 3의 프로그램을 고쳐 1단부터 9단까지를 한 단에 한 줄씩 출력하라. 문제 전문과 실행 예시는 [연습 문제 4](Exercises.ko.md#연습-문제-4-구구단-전체-출력)에 있다.

### 풀이

**접근 방법:** 연습 문제 3의 반복 전체를 단 `dan`을 1부터 9까지 바꾸는 바깥 반복 안에 넣는다. 이렇게 반복문 안에 반복문을 넣은 구조가 중첩 반복이다([5강 8절](Concepts_Lecture.ko.md#8-중첩-반복)).

- **바깥 반복:** `dan`을 1부터 9까지 바꾼다. 입력은 받지 않는다.
- **안쪽 반복:** 연습 문제 3과 같이 `i`를 1부터 9까지 바꾸며 곱셈식을 출력한다. 한 단을 한 줄에 출력하기 위해 `end=" "`로 줄바꿈 대신 공백을 붙인다.
- **줄바꿈:** 안쪽 반복이 끝난 뒤 인수 없는 `print()`로 줄을 바꾼다.
- **카운터의 재설정:** 단마다 `i`를 1부터 다시 세어야 하므로 `i = 1`을 바깥 반복의 본체 안, 안쪽 반복의 바로 앞에 둔다.

**코드:**

```python
dan = 1
while dan <= 9:                  # outer loop: tables 1 to 9
    i = 1                        # reset the multiplier for each table
    while i <= 9:                # inner loop: multipliers 1 to 9
        print("%s*%s=%s" % (dan, i, dan*i), end=" ")
        i = i + 1
    print()                      # line break after each table
    dan = dan + 1
```

**실행 결과:**

```text
1*1=1 1*2=2 1*3=3 1*4=4 1*5=5 1*6=6 1*7=7 1*8=8 1*9=9
2*1=2 2*2=4 2*3=6 2*4=8 2*5=10 2*6=12 2*7=14 2*8=16 2*9=18
3*1=3 3*2=6 3*3=9 3*4=12 3*5=15 3*6=18 3*7=21 3*8=24 3*9=27
4*1=4 4*2=8 4*3=12 4*4=16 4*5=20 4*6=24 4*7=28 4*8=32 4*9=36
5*1=5 5*2=10 5*3=15 5*4=20 5*5=25 5*6=30 5*7=35 5*8=40 5*9=45
6*1=6 6*2=12 6*3=18 6*4=24 6*5=30 6*6=36 6*7=42 6*8=48 6*9=54
7*1=7 7*2=14 7*3=21 7*4=28 7*5=35 7*6=42 7*7=49 7*8=56 7*9=63
8*1=8 8*2=16 8*3=24 8*4=32 8*5=40 8*6=48 8*7=56 8*8=64 8*9=72
9*1=9 9*2=18 9*3=27 9*4=36 9*5=45 9*6=54 9*7=63 9*8=72 9*9=81
```

각 줄의 끝에는 `end=" "`가 붙인 공백이 하나 있다. 바깥 반복이 9번, 안쪽 반복이 9번 실행되므로 곱셈식은 모두 $9 \times 9 = 81$개 출력된다. 두 반복의 횟수가 모두 정해져 있으므로 `for`문으로 쓰면 더 짧다.

```python
for dan in range(1, 10):
    for i in range(1, 10):
        print("%s*%s=%s" % (dan, i, dan*i), end=" ")
    print()
```

이 프로그램의 출력은 위의 `while`문 프로그램과 같다.

> **주의:** `i = 1`을 바깥 `while`문 앞에 한 번만 두면, 1단을 출력한 뒤 `i`가 10으로 남아 2단부터는 안쪽 조건 `i <= 9`가 처음부터 거짓이 된다. 그러면 첫 줄에 1단만 출력되고 나머지 8줄은 빈 줄이 된다. 안쪽 반복의 카운터는 바깥 반복이 새로 시작될 때마다 초기화해야 한다.

## 연습 문제 5: for문을 while문으로 바꾸기

**문제:** `range(1001)`로 반복하는 `for`문을 `while`문으로 바꾸라. 문제 전문은 [연습 문제 5](Exercises.ko.md#연습-문제-5-for문을-while문으로-바꾸기)에 있다.

### 풀이

**접근 방법:** `range(1001)`은 시작값 0, 종료값 1001, 증가값 1인 범위이다. [5강 7.1절](Concepts_Lecture.ko.md#71-변환-방법)의 대응에 따라 세 부분을 만든다.

- **초기화:** 첫 요소는 시작값 0이므로 반복 전에 `i = 0`으로 둔다.
- **조건:** 요소가 종료값 1001보다 작은 동안 반복하므로 `while i < 1001:`이다.
- **갱신:** 증가값이 1이므로 본체 끝에 `i = i + 1`을 둔다.

본체 `sum = sum + 1`은 `i`가 아니라 1을 더하므로, 이 프로그램은 본체가 실행된 횟수를 센다. `range(1001)`의 요소는 0부터 1000까지 1001개이므로 `sum`은 1001이 된다.

**코드:** 두 프로그램의 결과를 비교하기 위해 끝에 `print(sum, i)`를 덧붙였다.

```python
sum=0
for i in range(1001):
    sum=sum+1
print(sum, i)
```

```python
sum = 0
i = 0                    # initialization: first value of range(1001)
while i < 1001:          # condition: i has not reached the stop value
    sum = sum + 1
    i = i + 1            # update: step of range(1001)
print(sum, i)
```

**실행 결과:** 첫 번째는 `for`문, 두 번째는 `while`문의 출력이다.

```text
1001 1000
```

```text
1001 1001
```

두 프로그램의 `sum`은 1001로 같다. 반복이 끝난 뒤의 `i`는 다른데, `for`문은 마지막 요소 1000을 남기고 `while`문은 조건을 거짓으로 만든 1001을 남기기 때문이다.

> **참고:** 본체가 `sum = sum + i`였다면 0부터 1000까지의 합을 구하는 프로그램이 되며, 결과는 $\frac{1000 \times 1001}{2} = 500500$이다. 변환 방법은 본체의 내용과 관계없이 같다.

## 연습 문제 6: while문을 for문으로 바꾸기

**문제:** 합이 10000 이상이 될 때까지 1, 2, 3, ...을 더하는 `while`문을 `for`문으로 바꾸라. 문제 전문은 [연습 문제 6](Exercises.ko.md#연습-문제-6-while문을-for문으로-바꾸기)에 있다.

### 풀이

**접근 방법:** 먼저 원래 프로그램이 하는 일을 분석한다. `i`는 1부터 1씩 커지고, `sum`에는 `i`가 차례로 더해진다. 조건 `sum < 10000`은 더하기 전에 검사되므로, 반복은 합이 처음으로 10000 이상이 되는 순간 끝난다. 1부터 $k$까지의 합은 $k(k+1)/2$이며, 이 값은 $k = 140$일 때 $140 \times 141 / 2 = 9870$이고 $k = 141$일 때 $141 \times 142 / 2 = 10011$이다. 따라서 141을 더한 뒤 `sum`은 10011, `i`는 142가 되고 반복이 끝난다.

이 반복은 횟수가 미리 정해져 있지 않고 조건으로 끝나므로 `while`문에 알맞은 문제이다([5강 7.2절](Concepts_Lecture.ko.md#72-반복문의-선택-기준)). `for`문으로 바꾸려면 다음 두 가지가 필요하다.

- **충분히 큰 범위:** `for`문은 반복할 범위를 미리 정해야 하므로, 실제로 필요한 횟수보다 넉넉한 `range(1, 10001)`을 준다. 한 번 더할 때마다 합이 적어도 1씩 커지므로 이 범위 안에서 합은 반드시 10000에 도달한다.
- **`break`로 끝내기:** 원래의 조건이 거짓이 되는 순간, 즉 `sum >= 10000`이 되는 순간 `break`로 반복을 빠져나간다([5강 9.1절](Concepts_Lecture.ko.md#91-break문)).

원래 프로그램은 조건을 본체보다 먼저 검사하므로, 같은 순서를 지키려면 `break` 검사를 본체의 맨 앞에 둔다.

**코드:** 결과를 비교하기 위해 두 프로그램의 끝에 `print(sum, i)`를 덧붙였다.

```python
i=1
sum=0
while sum<10000:
   sum=sum+i
   i+=1
print(sum, i)
```

```python
sum = 0
for i in range(1, 10001):
    if sum >= 10000:     # the while condition, tested before each addition
        break
    sum = sum + i
print(sum, i)
```

**실행 결과:** 두 프로그램의 출력은 모두 다음과 같다.

```text
10011 142
```

`for`문은 `i`가 1부터 141일 때 더하기를 수행하고, `i`가 142일 때 맨 앞의 검사에서 `sum`이 10011이므로 `break`로 빠져나간다. 그래서 `sum`과 `i`가 원래 프로그램과 같다. 조건을 본체의 맨 앞에서 검사하면 `sum`의 초깃값이 이미 10000 이상인 경우에도 한 번도 더하지 않는다는 `while`문의 성질까지 그대로 유지된다.

검사를 더하기 뒤에 두는 다음 형태도 많이 쓴다.

```python
sum = 0
for i in range(1, 10001):
    sum = sum + i
    if sum >= 10000:     # tested after each addition
        break
print(sum, i)
```

```text
10011 141
```

`sum`은 같지만 `i`는 141이다. 이 형태는 141을 더한 직후에 빠져나가므로 `i`가 하나 더 커지지 않는다. 또 이 형태는 `sum`의 초깃값과 관계없이 적어도 한 번은 더한다. 반복 뒤에 `i`를 사용하지 않는다면 두 형태 모두 올바른 변환이다.
